#### Answering your timer-units question

**I picked seconds, in one place, and the constants stay in milliseconds.**

`update(time, delta)` gives `delta` in **milliseconds**. Physics wants **seconds**, because the accelerations you gave are px/s² — `ACCEL 2200` only means "2200 px/s²" if `dt` is in seconds. So the scene will convert once:

```ts
const dt = Math.min(delta, MAX_DT_MS) / 1000   // seconds
```

Coyote and buffer are the classic place this goes wrong: `COYOTE_MS` is 90, and if you tick it with a seconds-based `dt` you subtract ~0.016 per frame and the timer lasts about 90 seconds instead of 90 ms. Two ways to avoid it — tick timers in ms with the raw `delta`, or store them in seconds and divide the constants once. I chose **store the timers in seconds**, with a single conversion at the top of `Player.ts`:

```ts
const COYOTE = COYOTE_MS / 1000
const JUMP_BUFFER = JUMP_BUFFER_MS / 1000
```

Reason: then `dt` has exactly one unit everywhere inside the controller, so there's no second unit to mix up later when dash cooldown and the freeze window arrive at step 4. The constants stay in ms because that's the unit you tune in. I'll write it that way in step 3 — say the word if you'd rather the timers tick in raw ms.

#### The pause check found a real bug, and I fixed it

**The simulation is pause-safe by construction** — every clock is `dt`-accumulated, so a paused scene freezes all of them. Modelling a pause the way a paused scene actually behaves (stop calling update, then carry on) gives the strongest form of the claim, and all three of your cases pass it:

- **mid-slash**: a two-second pause inside the active window — the swing runs **identically across all 60 frames**, and the seal is cut exactly once.
- **mid-dive**: a three-second pause — the bat's path changes **by not one pixel**, ends in the same state, costs the same hit.
- **mid-fan-warning**: a five-second pause — still warning on resume, and the whole on/off schedule afterwards is **unshifted over 480 frames**.

**But input was not pause-safe.** Phaser resets a scene's keys when it pauses — `scene.sys.events.on(SceneEvents.PAUSE, this.resetKeys)` in its own `KeyboardPlugin.js:226`. So every key reads *up* on the first frame back. `Input` derives its edges against **its own** previous frame, so a jump key held before the pause was reported as **released** — firing `JUMP_CUT` and clipping a jump in mid-air. The same flag drives the glider, so a pause mid-glide stowed the wing too.

Measured: **a jump rising at −410 px/s continued at −380 with the fix, and was cut to −155 without it.** The test asserts both, so it shows the fix doing something rather than just passing. The fix is `Input.resync()` — seed the held flags from the live keys without producing edges — called from a `RESUME` listener.
